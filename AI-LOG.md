# AI Collaboration Log: rupee-kit

This log records the prompts used, AI suggestions received, and human engineering decisions made during the debugging and auditing process for `rupee-kit`.

| What I asked | What AI gave me | What I kept or changed, and why |
| --- | --- | --- |
| "Why does `1.005.toFixed(2)` return `'1.00'` in JavaScript, and how to implement true half-up rounding for rupee paise?" | An explanation of IEEE 754 floating-point inaccuracies where 1.005 is represented as `1.0049999999999998934...`, and suggested adding epsilon or using integer arithmetic. | Kept the epsilon-stabilized floor approach `Math.floor(Math.abs(amount) * 100 + 0.5 + 1e-9)` because it cleanly handles exact half-way thresholds across bills without third-party dependencies. |
| "How to format numbers with Indian grouping where the last 3 digits form a group, and preceding digits group in pairs of 2?" | A regular expression using lookahead to insert commas every 2 digits before the last three digits. | Kept `rest.replace(/\d(?=(?:\d{2})+$)/g, "$&,")` after testing it against edge cases (1 lakh, 10 lakh, 1 crore, 25 crore). It avoids regex backtracking issues. |
| "Why did `parseINR('Rs. 1,20,000')` return null when commas were supposedly removed?" | Explanation that `String.prototype.replace(',', '')` only replaces the first comma in JavaScript, leaving subsequent commas in place. | Kept `value.replaceAll(',', '')` so that both Indian (`1,20,000`) and Western (`120,000`) comma styles are cleaned in a single native pass. |
| "How to guarantee that `splitAmount(total, people)` shares always sum to total exactly, distributing leftover paise to the first people?" | An algorithm calculating integer total paise, integer division for base share, modulo for remainder paise, and adding 1 paisa to the first remainder shares. | Implemented this exact integer-based remainder distribution logic. It is mathematically guaranteed to sum to the exact total down to the paisa. |
| "What is the difference between GST exclusive and inclusive formulas when calculating base and tax?" | Mathematical breakdown showing inclusive base is `(price * 100) / (100 + rate)` and tax is `price - base`, whereas exclusive tax is `(price * rate) / 100`. | Replaced the incorrect exclusive formula in `gstFromInclusive` with the inclusive formula from `SPEC.md`. |
| "How to enforce Indian Standard Time (IST, UTC+5:30) in `formatDateIN` regardless of whether Node runs in London (UTC) or India?" | An explanation of how Date getter methods use local system timezone, and suggested shifting epoch milliseconds by `+330` minutes and reading UTC calendar methods. | Used `const istDate = new Date(date.getTime() + IST_OFFSET_MS)` with `getUTCDate()`, `getUTCMonth()`, and `getUTCFullYear()`. Verified that it passes both in local IST and under `TZ=UTC`. |
| "Why did `slugify(' Hello, World! ')` leave multiple hyphens?" | Pointed out that `.replace(/-+/, '-')` lacked the global flag `/g`, collapsing only the first run of hyphens. | Added the `/g` flag and added edge-trimming regexes to ensure no leading/trailing hyphens survive, even after slicing to 60 characters. |
| "How to count human-perceived characters including family emojis (👨‍👩‍👧) and Hindi letters (कि) in `truncate`?" | Suggested using Node.js built-in `Intl.Segmenter` with `granularity: 'grapheme'` rather than string `.length`. | Used `Intl.Segmenter` to count grapheme clusters. Also identified that the starter test incorrectly expected `"Hello…"` (6 chars for max 5) and corrected it to `"Hell…"` according to `SPEC.md`. |

One thing AI got wrong was initially suggesting `text.slice(0, max) + "…"` and claiming the starter test `"Hello…"` was correct, which violated the strict requirement in `SPEC.md` that the truncated result must have exactly `max` characters counting the ellipsis.
